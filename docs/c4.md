# C4: concurrent collection and compaction

**Draft, not ready to merge.** The default VM still uses the copying collector. The Linux x86-64 `NO_PLATFORM=1` binary has an opt-in concurrent collector for compatible images. It uses the real interpreter heap, not the model arena. It imports the standard stage-2 image, including its weak arrays.

## Live interpreter path

```sh
make test-c4-live
# For an already built, compatible image:
vm/build/c4/samaltak --c4 --eden 1 --max-heap 32 image --headless
```

Build the image with the normal platform VM; running an image in C4 mode requires the separate headless VM. In C4 mode `--eden` sets the allocation threshold for starting a cycle, not the size of a nursery. Set `SAMALTAK_C4_STATS=1` for the exit counters.

- A dispatch checkpoint arms the epoch and records stack/frame extents. It publishes at most 64 precise roots per visit. C stack and frame write barriers save overwritten values until their slice is published. Native calls are synchronous in this configuration; pushed C locals may not cross dispatch. Method-cache entries are not retained across dispatch. Heap Context scans use the arm-time live stack prefix, not the inactive tail.
- The worker reads atomic reference mirrors and side metadata, never raw object words. Reference stores shade the old edge for snapshot-at-the-beginning and shade the new edge as well. A claimed object uses its own queue link, so there is no log overflow or overflow remark. Raw byte and word payloads aren't traced.
- After root sealing and trace drainage the worker proposes close. It does not drain again until the mutator replies. The mutator acknowledges only with an empty inbox; if a barrier enqueued anything before the poll, marking resumes. Release/acquire handoffs publish the epoch, the root seal, the close decision and reclaimed blocks.
- Weak reads use the atomic mirror. Before close ACK they can shade the referent; after ACK they return nil for white referents. The worker clears weak slots before publishing any swept blocks. The mutator signals the image finalization semaphore, including during idle waits.
- Sweep publishes exact-size blocks for reuse. Allocation never waits for a cycle, scans the heap or enters legacy GC. A no-fit request can fail even when more space will become available later. Exact-size reuse does not prevent fragmentation. The mirror also costs additional memory; `--max-heap` bounds the object arena, not total RSS.

**Not supported:** platform/UEFI execution, JIT, ephemerons, snapshot saves, general `becomeForward:`, class conversion, synchronous GC requests, unrestricted reflective modification of Context stack ranges. CompiledMethod bytecode and literal storage references are write-once, and literal storage must be strong: interpreter frames borrow those bodies. Weak fixed-field boundaries are frozen per object at import/publication. Replacing the CompiledMethod special-object entry is also unsupported. Unsupported paths must fail, not silently substitute legacy collection or retain weak referents as strong. This mode is not a replacement for the default.

## Moving two-slot objects

Use `--c4-moving` instead of `--c4`. The lane admits only newly allocated
exact `Point`, `Association`, and `Message` instances with two fixed,
strong pointer slots. Their class oops are taken from the relocated image
specials, checked as imported object starts, and rooted each cycle.
Imported instances, subclasses, weak owners, classes, Contexts, methods
and literal/bytecode storage remain pinned and collectible.

An interpreter frame may retain a physical pointer into a pinned literal
table, not into an Association. The table's entries hold logical oops;
literal-variable bytecodes resolve the Association for a load and use a
barrier for a store. Message construction (including doesNotUnderstand:)
and slot access also use logical oops, with no native borrow of their fields.
The worker reads only the shadow graph. Raw payload views reject movable
objects, as does installation of movable code storage. The no-JIT,
headless restriction still applies.

Four 16 KiB regions come from the same `--max-heap` arena; one is reserved
for evacuation. The 1,536 handles and their metadata are capped separately.
When the lane fills, allocation tries C4's pinned allocator, never legacy
GC or a wait. A sealed source is inspected after weak clearing and sweeping
finish. Each dispatch visit inspects at most 64 records and copies at most
4 KiB. Live copies preserve the header, class, and fields. Dense regions
can be skipped; dead handles recycle only after source retirement.

`SAMALTAK_C4_STATS=1` reports moves per class, released regions, source reuse,
pinned fallbacks, and per-visit maxima. The native test leaves a pinned
literal view in place across evacuation, verifies both non-Point body
addresses change, and poisons the old addresses. The live gate
`tests/vm/c4-live/run-moving-general.sh build/samaltak.image` uses a standard
stage-2 image to exercise a compiled literal binding across collections,
a VM-created Message, weak aliases and clears, and per-class movement.

## ByteString widening

An exact ByteString can forward to an exact WideString without a legacy
collection or a synchronous repair. This is one hop, with the target's
identity and identity hash. A live raw alias keeps its forwarding cell
reachable; strong reference loads heal their slots, while weak slots follow
the target and are healed or cleared before reuse. The source remains
ineligible for reuse while a strong raw alias still needs it. The interpreter
rejects forwarding sources that are borrowed as bytecode storage.

## Heap enumeration (interpreter WIP)

`Behavior>>allInstances` answers the same kind of Array as the copying VM.
C4 requires a rebuilt image: its Smalltalk fallback submits a singleton
request and waits on a private Semaphore. The scheduler can run other
Processes; the VM does not join the worker, busy-wait, or walk the heap
on the mutator. Completion stores into a private carrier before signaling.

1. After any in-flight GC cycle finishes, a dispatch/idle checkpoint
   freezes a version and the interpreter's root extents. Existing root
   barriers and cursors deliver the cut roots in slices. Class and strong
   slot writes preserve the first old atomic shadow value per version;
   forwarding publication preserves the old forwarding word. The worker
   reads either this old value or the unmodified shadow, with acquire
   recheck after reading the shadow.
2. Once roots are sealed, the worker traces this exact strong view, not the
   collector's SATB mark set. It uses cut-time class, Context stack prefix
   and forwarding edges, skips weak suffixes, and emits each reachable
   identity at most once. Forwarding cells are not candidates; movable
   Points, Messages and Associations use their logical handle. The request's own Semaphore and carrier
   can be traced but are excluded from the result.
3. Until the mutator publishes the result, no GC sweep or region retirement
   runs; old live identities cannot alias reuse. Allocations continue in
   other Processes, using only space already free or above the high-water
   mark. A ByteString query fails if a forwarding mutation makes its view
   potentially noncanonical before handoff. WIP bounds: one request,
   4,096 result identities, a capped sized allocation, and at most 64
   result stores per checkpoint. Overflow or allocation failure fails the
   primitive; it never returns a partial Array or falls back to legacy GC.

The cut, not the return instant, defines reachability. A cut-live object may
lose its last other strong edge while the worker runs. Delaying reclamation
can increase allocation pressure. On first use a lazy side mapping reserves
about 2.5× the pinned arena size plus about 2 MiB for roots; this is outside
`--max-heap` and resident usage depends on touched pages. Concurrent
requests fail rather than queue.

`tests/vm/c4-live/run-enumeration.sh build/samaltak.image` compares the
headless paths. Native gates cover a stalled enum worker, multiple stores
to the same edge, weak and Context-tail exclusions, forwarding races,
logical handles of every movable class and overflow.

## Work still required

1. **Native lifetime.** Audit native borrows, callback roots and large objects before enabling platform finalizers; keep raw payloads in place until ownership is explicit.
2. **Broader relocation policy.** Extend the two-slot lane only after auditing all roles of new movable layouts. Add source selection and size classes without unbounded dispatch work, and quantify fragmentation and pinned fallback.
3. **Compiled code.** The tier-wide atomic request/ack protocol preserves entry and loop polls. Cover architecture-specific live maps, deopt, class/method references, literal pools, inline allocation, stores, barrier slow paths and code-cache lifetime on x86-64 and arm64.
4. **Image semantics.** Complete enumeration under pressure, and implement `become:` and snapshots without a fork, stop-the-world remark or fallback. Exercise processes, Context reflection, native handles, identity and weak behavior against the default collector. No default switch until all supported image paths work.

## Gates

- `make test-c4`: Smalltalk model, legacy frozen-graph mark verifier and, on Linux x86-64, native arena and live interpreter fixture. The fixed native arena and Smalltalk model do not establish production concurrency.
- Live fixture: repeated allocation above the arena cap, exact reuse, stable live graph across mutation and deep frame roots, zero legacy collection counts, and an interpreter differential. `tests/vm/c4-live/run.sh latency` compares fixed-batch mutator latency.
- Standard image: `tests/vm/c4-live/run-weak.sh build/samaltak.image` exercises Process registry growth and loss of dead entries, weak allocation, fixed fields, overlap and shallow copy, idle finalization, and reclamation with no forced or legacy collection.
- Native gates: close races, an indefinitely stalled worker, bounded OOM, independent reachability oracle and sanitizers. The two-slot lane additionally checks physical relocation, handle reuse after weak clear, exact source-address reuse, and dense/empty/stalled-worker behavior. Report throughput, maximum and tail latency, and peak RSS against main.
- VM changes also need the headless parts of core and the JIT matrices locally. Display tests run in CI, not locally on a machine without a GPU.
