# C4: production roadmap

**No production C4 collector yet.** The VM still moves objects synchronously. `SAMALTAK_VERIFY_MARK=1` compares an independent trace of the frozen full-GC graph with the copying collector's forwarding results: a tracing check, not a concurrency test.

The [native test arena](../tests/vm/c4-native/README.md) holds up to 64 live cells with two strong slots each. A real snapshot-at-the-beginning (SATB) worker traces while the mutator keeps writing. Closure is up to the mutator: it checks completion without waiting and cancels reclamation if a store published a snapshot-white handle. The mutator can also move one fixed-size cell per call between epochs without changing its handle. This is not concurrent evacuation.

[`apps/C4Prototype`](../apps/C4Prototype) is an independent cooperative Smalltalk model, not the native protocol. Interleave mutator calls between `C4Heap>>step` calls after `startCycle`; each step examines at most one slot. Host locals aren't roots: use `rootAt:put:` and reload from roots or slots after a cycle.

**No stop-the-world fallback in future C4 mode.** Checkpoints do bounded work without waiting. Exhaustion, explicit GC requests and unsupported paths never invoke legacy collection.

## Next changes

**Next milestone:** scalable interpreter root handles with resumable publication, integrated with allocation, regions and reference barriers. Account for live temporaries, pushed roots and changing Context stack ranges. Cover class/body words, literals and overlapping copies; keep raw GC, image relocation and unpublished initialization explicit.

Use a single atomic poll request/acknowledgment protocol: keep the stack limit mutator-owned and stop any-thread requests from writing plain JIT poll fields. Preserve compiled entry and loop polls before bringing either JIT tier into C4.

## Interpreter protocol to prove

- **Arm/mark:** Arm the barrier before acknowledging the epoch. Publish precise roots in chunks and account for changing root ranges. Use atomic shared reference words and treat new allocations as live. The worker proposes closure after sealed work drains; the mutator commits only if no work raced the seal. Otherwise retry with barriers on. Weak clearing must not erase a racing store.
- **Move/heal:** Seal regions and reserve destinations. Initially only the mutator copies, in bounded quanta, with writes to the source excluded. Initialize before release-publishing forwards; resolve with acquire. Heal slots with CAS against the exact old value.
- **Retire:** Heal heap and roots, then require acknowledgment that aliases were dropped. Release source space and forwarding metadata only after older access scopes and scans exit. Reject stale references on reuse; preserve identity hash and compare canonical identities.

**Native lifetime:** Use updateable handles or mapped slots across safepoints; reload and rebuild interior pointers. Raw borrows cannot poll, allocate, block or call back. Async I/O and GPU use off-heap buffers. Track borrow exit and pin/handle release. Account for JIT roots and pools before enabling either tier.

**Bounds:** Start with 64 roots, 256 slot operations and 4 KiB copied per mutator quantum: work caps, not latency guarantees. Keep large or raw payloads in place until safe. Preallocate metadata and relocation space; use rescan bits for mark overflow. On pressure, allow one bounded assist and retry, then use preallocated OOM. Never wait or spend relocation space on application allocations.

**First integration:** Headless Linux x86-64 interpreter only. Reject JIT, other targets, platform/GPU paths, snapshot saves, `become:`, synchronous GC, heap enumeration, weak references, finalizers and ephemerons until supported. Leave legacy mode unchanged.

## Gates

- `make test-c4` runs the model and the `C4-MarkTests` VM fixture (exactly one mark-verifier witness under tiny eden). On Linux x86-64 it also runs the native arena against `$(OUT)/samaltak.image`, with artifacts under `$(OUT)/c4-native-test`. `test-core` runs this target and enables both verifiers in kernel/compiler stress.
- Boundary changes: `make test-core`, `make test-jit` (including deopt) on arm64 and x86-64; cover roots across allocations, bulk overlap, weak slots, snapshot and `become:`. Check allocation/send performance against main.
- Native gates: force poll/ack, last-root/store vs. close, overflow, stalled worker and OOM races; compare live sets and run sanitizers. Moving adds publish/heal/store races and retire vs. delayed readers/address reuse. Require bounded work and zero legacy GC entries; report max/p99.9 mutator pause, throughput and peak memory on a fixed workload before enabling C4.
