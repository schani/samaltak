# Samaltak UI stack spec

How the image draws, composites, and handles input. Everything here is Smalltalk except the platform primitives (`vm/platform/README.md`). Visual reference: the Blue Book + pi-orb prototype (`prototypes/1-classic/`, especially `themes/blue-book.css`, `types/pi-orb.css`, `debugger.css`, `profiler.css`, and `prototypes/screenshots/bb-piorb.png`). The real system should look like that prototype, only better.

**Layering** (enforced by the image builder, which rejects violations with file:line): a package may reference globals of packages on its own layer, the layer directly below, and layer 0 (Kernel, System, Compiler). Exceptions, all declared in `src/packages.txt`:

- Graphics-Canvas' drawing vocabulary — `Canvas`, `Color`, `Font`, `Form`, `FragmentShader` (`Point`, `Rectangle` are Kernel) — may be used from layer 3 up (`export Graphics-Canvas 3 Canvas Color Font Form FragmentShader`): widgets and tools draw.
- Test packages may list the packages their fixtures need (`Tests-Tools 5 uses UI-Windows Graphics-Canvas`).

Tools (5) never name `Window`, `World` or `UIWindows`: UI-Widgets' `Desktop` forwards to them (`Desktop current` is the World, `Desktop newWindow` a Window, plus the World's hooks and the startup action). Lower layers reach higher ones only late-bound (`Smalltalk at: #Tools ifAbsent: […]`).

## Graphics-GPU (layer 1)

Thin, WebGPU-shaped objects over the `gpu*` primitives, each holding a platform handle and releasing it when asked (`GPUPlatform` is the gateway: the VM's primitives, `GPUPrimitives`, or where the image drives the machine itself, on UEFI, `FirmwareDisplay` for windows and events and `SoftwareGPU`, a GPU device in Smalltalk over the raster primitives; docs/uefi.md): `GPUDevice` (factory for everything below; `GPUDevice default`), `GPUShader`, `GPUPipeline`, `GPUTexture` (width, height, format), `GPUSampler`, `GPUBuffer`, `GPUCommandBuffer` (`beginPassOn:clear:` → `GPURenderPass`, `blit:to:`, `submit` → `GPUFence`), `GPURenderPass` (`pipeline:`, `vertexBuffer:`, `texture:sampler:slot:`, `uniforms:`, `scissor:`, `viewport:`, `draw:from:`, `end`), `GPUFence` (`wait`, `isDone`), `GPUSwapchain` (per window). Handles die with the process; on image startup every GPU object is re-created lazily (they hold their creation parameters).

## Graphics-Canvas (layer 2)

- **Fonts**: `TrueTypeFont` parses a `.ttf` (`cmap` format 4/12, `glyf`/`loca`, `hmtx`, `hhea`, `head`, `OS/2`; for color glyphs `COLR` v0, `CPAL` and the ligatures of `GSUB`'s `ccmp` feature) in Smalltalk. `Font` = typeface + pixel size + device scale; answers metrics (ascent, descent, line height, advance of a Character, width of a String). `GlyphAtlas` rasterizes glyph outlines (quadratic Béziers, non-zero winding, exact area coverage) into an R8 atlas texture at device resolution, lazily, caching glyphs; atlases for the standard fonts are pre-rasterized in stage 2 and live in the image. `aFont glyphFor: $g` answers a `GlyphForm`: the glyph's coverage as drawn (read back from its atlas page; alpha = coverage). Standard faces: Iosevka Etoile Regular/Bold/Italic (UI, text) and JetBrains Mono Regular/Bold/Italic (code), the upstream releases, in `fonts/`. Stage 2 loads every face the system uses into the image (`Font class>>imageFaceNames`: the standard faces, the fallback faces and Twemoji, 19 MB of the image) and compacts each to the tables read and the outlines the `cmap` reaches (about 1 MB a standard face; the Noto files hardly shrink), but for Twemoji, whose layers and ligatures are glyphs the `cmap` does not reach. A face stays the bytes of its file, parsed lazily as glyphs are needed. The image keeps the faces across snapshots and never reads a font file at run time, so it runs without `fonts/` and on a VM without file primitives (UEFI, docs/uefi.md). A code point the face lacks comes from the first fallback face that has it (`Font class>>fallbackFaceNames`): Iosevka Etoile Regular (for the code font: Greek Extended, more arrows, math, Braille), Noto Emoji (monochrome), Noto Sans Symbols 2, Noto Sans SC (Han in Simplified Chinese forms, the widest Han coverage of the Noto CJK faces; kana), Noto Sans KR reduced to Hangul. The fallback glyph is drawn at the font's em size on its baseline with its own advance (no cell width). The Noto files are static wght 400 instances of Google Fonts' variable fonts without hinting or layout tables, made by `tools/fallback-fonts.py` (pinned upstream commit and fontTools version). Resolution is cached per code point. Controls and default-ignorable characters (ZWSP, joiners, bidi controls, variation selectors, BOM, tags) draw nothing and advance 0; a code point no face has draws as a hollow box as tall as a capital with its hex digits. **Color emoji** come from Twemoji (`fonts/Twemoji.ttf`, Mozilla's COLR build v0.7.0, Emoji 14, subset by `tools/fallback-fonts.py` to all its glyphs with the `ccmp` ligatures; Apache-2.0, artwork CC-BY-4.0, `fonts/twemoji-LICENSE.md`). It is not a fallback face (its `cmap` maps digits, `#`, ZWJ, U+FE0F and tags to empty glyphs) but consulted per grapheme cluster by `ColorEmoji` (`Font class>>emoji`): a cluster with U+FE0E is text; otherwise its code points but U+FE0F go through Twemoji's `cmap` and ligatures (longest first, U+FE0F in their components ignored), the empty glyphs left are dropped, and the cluster is color if glyphs remain, all of them color glyphs, and it has U+FE0F, U+20E3, ZWJ, an emoji modifier, two regional indicators or tags, or is one Emoji_Presentation code point. So 😀, 👨‍👩‍👧, 🇩🇪, 👍🏽, 1️⃣ and ©️ are color, a bare digit, # or © stays text, and a ZWJ sequence Twemoji has no ligature for shows its parts in color; Emoji 15 and later code points come from monochrome Noto Emoji. A color glyph is drawn as a quad per `COLR` layer in its `CPAL` color (the text color for palette index 0xFFFF, the text color's alpha for all), so emoji keep their colors when selected; layers are rasterized into the atlas at the font's em size (subpixel phase 0, keyed by glyph index), centred on the font's ascent and descent, and the cluster advances by its glyphs' advances (an em each). `Canvas>>drawString:`, `Font>>widthOf:` and `indexAt:in:` agree on this (`Font>>colorClusterEndAt:in:to:`); text with no code point from U+203C on never looks for clusters. The atlas only grows: glyphs rasterized at run time (CJK text: thousands, four subpixel phases each) add 2048² pages that a saved image keeps.
- **Canvas**: the only drawing API widgets see. Coordinates in points (float). `fillRect:color:`, `strokeRect:color:width:`, `line:to:color:width:` (axis-aligned and diagonal), `drawString:at:font:color:` (baseline-free: `at:` is the top-left of the line box), `drawString:in:font:color:align:`, `image:in:` (a `Form`: Bitmap + extent, uploaded as a texture on demand), `pattern:in:` (procedural fills: `#halftone`, `#stripes` — computed in the fragment shader in device pixels), `clip:during:`, `translateBy:during:`, `alpha:during:`, `measure:font:`. A Canvas records into a **DisplayList**: a ByteArray of vertex data (pos float2, uv float2, color rgba8, mode/extra) plus a short list of batches (texture, scissor, first, count, and a move in whole device pixels the vertex shader adds). Once frozen, a DisplayList is never mutated. Retained drawing: `record: aBlock` answers a **DisplaySegment** of what aBlock drew; `replay: aSegment` on a later Canvas draws it again (copying its vertices, moved by whole device pixels) when scale, opacity and the clip relative to the origin match, else answers false; `drawFresh:` refuses all replays inside; `noteVolatile` marks what shows values computed while drawing.
- **Renderer**: owns the pipelines (MSL source in Smalltalk), uploads a DisplayList into a vertex buffer and encodes it into a render pass. One uber-shader with modes: solid, glyph (R8 coverage), image (RGBA), halftone, stripes.
- **FragmentShader**: an MSL fragment function (after a prelude: `ShaderIn` with uv and size) rendered over a texture of its own; `imageExtent:source:uniforms:` answers a **ShaderImage**, one immutable frame that `image:in:` draws like a Form: rendered when the Renderer first draws it (in a command buffer submitted before the frame's), again only when the texture lost its contents (new session). New source builds a new pipeline; source that does not compile keeps the old one and goes to `Renderer reportShaderError:`.
- **Color**: `Color r:g:b:a:` (floats), named colors, `alpha:`, `mixed:with:`; packs to rgba8.
- **Form**: Bitmap (32-bit RGBA) + width/height; `at:put:`, `fill:`; dirty tracking for texture upload; `pixelComponentNames` / `pixelComponentsAt:` (r g b a; a GlyphForm's coverage).
- **Vector graphics**: `VectorPath` (contours of lines and cubics; SVG path data with every command, arcs as cubics; rectangles with rounded corners, ellipses, polygons; affine transforms; flattened to polylines within a tolerance), `VectorPainter` (fills a path into a Form, non-zero or even-odd, with GlyphRasterizer's exact area coverage; strokes as quads with round or bevel joins and butt, round or square caps; premultiplied source over), `SVGImage` and `SVGReader` (the static SVG of logos and icons: `svg` with its viewBox, `g`, the basic shapes and `path`; fill, stroke and their opacities, fill-rule, joins and caps, as attributes or `style`, inherited; transforms; masks, clip paths, gradients, text and CSS not read). `(SVGImage fromFile: path) formWidth: 32 height: 32 color: Color ink` paints it, fitted and centered, `currentColor` as the given color.
- **PNGWriter**: encodes a Form or RGBA bytes as PNG in Smalltalk (stored-deflate blocks, CRC-32, Adler-32).

## UI-Windows (layer 3)

- **World**: the desktop (halftone pattern), the window list (z-order), focus, the top bar, the pointer, menus and toasts as overlay layers. `World current`.
- **Compositor**: a Process at priority 70 woken by the platform's vsync semaphore (`vsyncSemaphore:`), presenting at most 60 Hz (every second refresh on a 120 Hz display: presenting faster makes the Metal swapchain acquire block the single VM thread). When the refreshes are half a tick late (25 ms after the previous tick at 60 or 120 Hz) it ticks anyway: there is no display link while the display sleeps, and macOS slows it to about 10 Hz while the VM runs in the background role. Each frame: for every Layer whose content changed, render its latest frozen DisplayList into the layer's texture; then composite all layers onto the swapchain (and, when recording, into an offscreen target that is downsampled and read back), apply layer transforms (offset, scale, opacity), draw hard shadows; record a **FrameRecord** (start/end µs, per-Process CPU deltas from `Process>>cpuTime`, draw/raster/GPU times, GC counts/µs from `vmStats`). The compositor never waits for a window's Process: a busy window keeps its last frame and stays draggable.
- **Layer**: texture, bounds, transform, opacity, `latestDisplayList` (set atomically by the owning Process), dirty flag.
- **Window**: title, bounds, content (a Widget tree), its own **Process** (priority 40, named after the window) running an event loop over a `SharedQueue` of items that run themselves there (`deliverTo:`: blocks, WindowTimers, input events); redraws its content into a fresh Canvas when invalidated and publishes the frozen DisplayList to its Layer. Drawing is retained: each View replays its last drawing (`drawRetainedOn:`) unless it changed since; `invalidate` redraws a view and everything in it, a moved view is replayed moved, `Window>>invalidate` redraws everything. A view whose drawing reads other objects' state must invalidate when that state changes (`View verifyDrawing: true` compares every replay with drawing anew). Title bar (Blue Book: stripes when focused, title tab), close/collapse boxes, drag, resize from edges/corner, focus. `Window>>busy` indicator when its Process is computing (e.g. the Mandelbrot). Window open/close and focus changes animate.
- **InputDispatcher**: a Process at priority 60 that reads platform events (the input semaphore), tracks the pointer and modifiers, routes each event to the right Window's queue (pointer → window under the pointer or the one with capture; keys → focused window), and handles window-manager gestures (title-bar drag, resize, raise) itself so they stay live while a window's Process is busy. Remote input arrives through the same path (`injectEvent:`). Each platform event Array is decoded once (`UIEvent fromPlatform:`, event types named `UIEvent evMouseMove` … after the platform layer's PF_EV_ constants) into an input event or a host window event (HostResizeEvent, QuitEvent, FocusLostEvent, ScaleChangedEvent, PointerLeftEvent, ExposeEvent) that dispatches itself (`dispatchTo:`); drags and resizes are DragGesture / ResizeGesture objects.
- **Animation**: `Animation` tweens a property (number, point, rectangle, color: `interpolateTo:at:`; other objects jump at the end) with a duration and easing (`#easeOutCubic`, `#easeInOutQuad`, spring) on the compositor clock. Layer properties (offset, scale, opacity) are animated by the compositor itself — smooth even when the window's Process is busy. Widget animations (selection bars gliding between rows, the debugger's pc highlight moving between expressions, flame-graph zooms, tab cross-fades, toasts) re-render the window each frame while running. Durations 90–220 ms; subtle, never bouncy-cute. The compositor clock is `Animation now`: real time divided by `Animation timeScale` (`Animation timeScale: 10` is slow motion for every animation, toasts, tooltip delay, caret blink and the remote pointer's travel; World menu 'Slow motion', top bar tag '10× SLOW'; Tools use `Desktop animationTimeScale:`), continuous when the scale changes. Timers that are animation time use `Widget>>afterAnimationTime:do:`; Delays, refresh timers and timeouts stay real.
- **Snapshots**: an image saved while its World runs (World menu › Save image, `Tools saveImage`) resumes that World when started again with a display (`UIWindows startUp:` → `World>>resumeHidden:`): the windows (bounds, z-order, focus, content) and their Processes are as saved, so a Debugger still holds its suspended Process. The host window re-opens at the saved size (hidden per the new command line), GPU objects re-create their handles, a new Compositor and InputDispatcher start (fresh external semaphores), layers render again; layer and window animations jump to their end, toasts are dropped, Delays are rebased (`Delay shutDown`/`startUp`). The snapshotting Process continues after the snapshot; headless, the saved World is abandoned and the command line runs as in a fresh image.
- **AppWorld / AppWindow**: an application's World (docs/apps.md). Its host window is a window of the host's window manager and shows one chromeless AppWindow filling it, plus its overlays. There is no desk, no top bar (`World>>showsTopBar`) and no opening animation, and frames are presented only when something changed (`World>>presentsContinuously`). Closing the window quits.
- **Scheduling rule**: Smalltalk code that touches a window's widgets runs in that window's Process (`window do: [ ... ]` enqueues a block).

## Live changes

Accepted code takes effect on the running screen. `SystemChanges` (Kernel-Classes) announces every method added, changed or removed (Behavior) and every class defined (ClassBuilder) to subscribers, in subscription order (= load order, lower layers first), in the changing Process: `SystemChanges subscribe: #key do: [:change | ...]`, `change affects: aClass` (aClass or a subclass, either side), `SystemChanges silentlyDuring:`. Subscribers:

- `Color`: a change to Color drops the named-color palette (rebuilt on use).
- `Renderer`: a change to Renderer (its MSL source is `Renderer class>>shaderSource`, its GLSL source `glslShaderSource`) makes every Renderer build its pipeline again before its next render; if the source does not compile the old pipeline stays and `Renderer shaderErrorHandler:` gets the error (UI-Windows: Transcript + a toast with the compiler's first message). `pipelineVersion` counts rebuilds; the Compositor then renders every cached layer again.
- `Font`: a change to Font, GlyphRasterizer or TrueTypeFont resets the GlyphAtlas and every Font's glyphs; they are rasterized again on first use (~150 ms for the default desktop). GlyphAtlas allocation is serialized (window Processes rasterize concurrently).
- `UIWindows`: a change to a View subclass or to a class in Graphics-GPU, Graphics-Canvas, UI-Windows or UI-Widgets restyles `World current`: every window and overlay redraws its content without replays and its chrome; the top bar drops its fonts.
- `Theme`: a change to Theme or Color makes `Theme current` run its definition again (`refresh`: colors and metrics, fonts kept), publish its colors as Color's named colors (the chrome draws with `Color ultramarine`), and restyle the World.

The desk is `World>>drawDeskOn:`, drawn by the compositor every frame.

## Window ↔ content contract (UI-Windows defines, UI-Widgets implements)

UI-Windows (layer 3) defines the abstract classes; `Widget` (layer 4) subclasses `View`.

- **Events** (UI-Windows): `PointerEvent` (`type` #down #up #move #wheel #enter #leave, `position` (Point, local to the receiver when delivered), `globalPosition`, `button` 1 left / 2 right (also ctrl-click) / 3 middle, `clickCount` (2, 3 … only for a press the platform counted as a further click (its double-click interval) with the same button, within 5 points of the previous press and on the same window zone, view and item; else 1), `delta` for wheel, `modifiers`), `KeyEvent` (`type` #down #up, `key`: a Symbol for named keys — #left #right #up #down #return #enter #backspace #delete #escape #tab #home #end #pageUp #pageDown #space — or a lowercase Character for printable keys, `modifiers`), `TextEvent` (`string`), `TextEditingEvent` (an input method's composition, shown until a TextEvent commits it or an empty one cancels it: `string`, `cursor`, `selectionSize`, nil when not given). Modifiers answer `shift` `control` `option` `command` and `commandKey` (⌘ on macOS; Alt on Linux, where the platform layer reports Alt as cmd and Super as alt, and a key typed with cmd produces no text). Events come from the platform's 8-slot Arrays, real or injected, through the same path.
- **View** (UI-Windows): what a Window's content is. `owner`, `window`, `bounds` (in owner coordinates) / `extent`, `layout` hook called after resize, `drawOn: aCanvas` (local coordinates: 0@0 is the view's top-left; the window translates and clips), `children` (default: none), hit testing `viewAt: aPoint`, `handlePointer: evt` / `handleKey: evt` / `handleText: evt` / `handleTextEditing: evt` answering true when handled (default: bubble to owner), `wantsKeyboardFocus`, `focusGained` / `focusLost`, `cursorAt: aPoint` (#arrow #ibeam #hand #resizeEW #resizeNS #resizeNWSE #move), `clickItemAt: aPoint` (what a press hits, for multi-clicks: a ListView answers its row), `invalidate` (asks its window to redraw), `contextMenuAt: aPoint` (answer a Menu model or nil), and the remote-control protocol (`remoteRole` `remoteLabel` `remoteState` `remoteName` `remoteChildren`, defaults derived from class and children).
- **Window**: `Window new title: aString; content: aView; bounds: aRectangle; open` (creates its Layer and its Process, priority 40, named after the title), `do: aBlock` (run in the window's Process), `sync: aBlock` (run there and answer its value; an Error in aBlock is signaled again in the caller, same exception with its original stack: `Exception>>freeze` / `resignal`), `invalidate`, `close`, `focus`, `isFocused`, `busy:` (shown in the title bar while true; the window manager stays live), `process`, `world`, `title:`, `keyboardFocus:` (a View), `requestAnimationFrames: aBlockOrAnimation` (redraw every compositor frame while it runs), and `Window>>openNotifier…`-style helpers left to Tools. Its Process loop: take the next event from its SharedQueue, deliver it to the content (with hit testing, pointer capture between down and up, keyboard focus), and redraw when invalid.
- **World**: `World current` — `windows` (front to back), `openMenu: aMenuModel at: aPoint` (overlay layer; the Menu view is a Widget, the World only hosts it), `toast: aString`, `activeWindow`, `bounds`, `topBar`.
- **Animation**: `Animation from: a to: b duration: ms easing: #easeOutCubic do: [:value | …]` runs on the compositor clock; started by a View via `self window animate: anAnimation`; Layer properties (`offset`, `scale`, `opacity`) animate in the compositor without involving the window's Process.

## UI-Widgets (layer 4)

`Widget` (bounds, owner, children, layout, `drawOn:`, event handlers `mouseDown:`/`mouseMove:`/`mouseUp:`/`keyDown:`/`textInput:`/`textEditing:`/`wheel:`, focus, `invalidate`, cursor, tooltip, `contextMenu`) and: Label, Button (Blue Book: 1px frame, inverted when pressed or default), ToggleGroup/Tabs, ListView (rows with optional icon/gutter cell/right-aligned muted text, selection that glides, keyboard navigation, scrolling, double-click, context menu), TextEditor (multi-line, caret, selection, mouse drag/double-click word, keyboard incl. word/line movement, undo, clipboard, scrolling, syntax highlighting via the Compiler's Scanner, marks: result/error/pc highlight ranges, do it/print it/inspect it/accept hooks; a facade over TextBuffer (text, line index, word boundaries, change listeners), TextLayout (rows and wrapping, column ↔ x, caret/selection rectangles, scroll offset), TextHighlighter (Scanner tokens, incremental rescans, styled runs) and TextUndoHistory (grouped typing)), Splitter, ScrollPane, PaneHeader (tiny tracked caps label + muted right text), StatusBar, Menu (popup, keyboard navigable, fades in), Toast, Notifier frame, ShaderView (a FragmentShader's picture: `shaderSource`, `uniforms` as float4 rows, `renderScale`; a new frame at each drawing). Layout: simple rows/columns with fixed/flexible sizes; no constraint solver.

**Application** (`Application`, docs/apps.md): a program that runs in an AppWorld of its own. A subclass answers `content`, and `bin/samaltak run <dir>` files in its package and runs it. **OmarchyTheme** (package UI-Omarchy, layer 4): the Theme of the Omarchy desktop, read from its theme files and fontconfig and kept current with them; installed at every start where Omarchy is (see Theme below).

**Text** (TextEditor, TextLayout, TextBuffer): characters are grapheme clusters; the caret, selection ends, clicks, backspace and delete, word ends and wrap breaks never fall inside one (é as e + U+0301, emoji ZWJ sequences, flags, skin tones, Hangul jamo). x is the font's width of the text between tabs as Canvas draws it (marks and joiners 0, CJK and emoji from the fallback faces wider than a cell, a color emoji cluster an em per glyph); a line of printable ASCII in a monospaced font takes the shortcut count × advance. Rows wrap after white space, else next to a wide (CJK) character, not before closing or after opening punctuation, else before the cluster that does not fit; an edit lays out again only the lines it touched. A word is a run of letters, digits, _ and marks, CJK and Hangul apart from other scripts. Typed DEL and C1 controls are dropped; line ends become LF. An input method's composition shows at the caret, underlined, the rest of the row moved right; it is in neither the text nor the undo history, keys without ⌘ go to the input method while it shows, and the editor reports the caret to the host window (`windowSetTextInputArea`) whenever it moves, so the candidates appear there.

**Theme** (`Theme current`, Blue Book): black on white; 1px black rules; hard 2px offset shadow on the focused window; halftone desk; ultramarine `#1b3a8c` as the only accent; selection by inversion in focused lists, a 1px box otherwise; fonts: UI Iosevka Etoile 13.5px, headers tracked capitals 10.5px bold, code JetBrains Mono 13px/20px.

**On an Omarchy desktop** the whole system follows the Omarchy theme (`OmarchyTheme`, UI-Omarchy), light or dark, and switches live with `omarchy theme set` and `omarchy font set`; elsewhere, headless, under `--test` or with `--theme blue-book` it stays the Blue Book. The Blue Book's character stays, its colors come from the theme's `colors.toml`: ink (`foreground`) on paper (`background`) for text, rules, frames, title stripes and inverted selection; greys mixed from the two; the one accent (`accent`) where the Blue Book has ultramarine; text selection `selection`; the desk `dark_background` with halftone dots in `muted`; the hard shadow `foreground` in light themes, black in dark ones; the Terminal's 16 colors as Omarchy's terminals have them (`Theme>>ansiColors`). The UI font stays Iosevka Etoile; code is drawn in the Omarchy typeface (fontconfig's `monospace`), which takes the place of JetBrains Mono wherever that is drawn (`Font substituteFace:with:`). The window system draws its chrome with the roles the current Theme publishes as Color's named colors (`Color ink`, `paper`, `ultramarine`, `shadow`, `desk`, `deskDots`; Blue Book values by default), so it follows any Theme.

**Remote-control hooks**: every Widget answers `remoteRole` (#window #list #item #editor #button #tab #menu #canvas #status …), `remoteLabel`, `remoteState` (Array of words like `selected` `focused` `dirty`), `remoteName` (stable slug used to build refs like `@w3.packages.kernel-numbers`), `remoteChildren`, and `remoteAction: #click|#select|…` where needed. The snapshot is computed in Smalltalk from the live widget tree.

## Tools (layer 5)

System Browser, Workspace, Transcript, Inspector, Process Browser, System Monitor, Mandelbrot, Terminal, File Browser, World menu, Notifier, Debugger, Breakpoints, Profiler, Agent (⌘J in a tool; UI-Agent and Tools-Agent, docs/agent.md), control service. Behavior and look follow the prototype (see `prototypes/1-classic/*.js` for the interactions and the default workspace text), with everything real: real classes and methods, real processes, real stepping, real samples. The Inspector shows a Form's pixels magnified (`PixelView`, ref `pixels`: integer zoom that fits, grid from zoom 6, wheel or + − 0; the hovered pixel's value in `pixel-status`; state `zoom=17 size=12x20 hover=6,12 value=252`): `(Font code glyphFor: $g) inspect`, then `samaltak-ctl hover @wN.pixels --at 6,12`.

**Terminal** (World menu "Terminal", `Tools openTerminal`, `Tools open: #terminal`): a login shell (`$SHELL -l`) in the repository holding the image's `src/`, on a pseudo-terminal (`PseudoTerminal`, System-Files, over the `pty*` primitives). `TerminalParser` interprets the program's output (UTF-8, C0, ESC, CSI incl. scroll regions, insert/delete, SGR 16/256/truecolor, DEC modes: alternate screen 47/1047/1049, application cursor keys, autowrap, cursor visibility, bracketed paste; OSC 0/2 title; device reports; DECRQM mode queries, answered with the current state of the modes above, insert and newline mode, and 2027 as permanently set) into a `TerminalScreen` (rows of `TerminalLine`: a character and a packed attribute per cell; 5000 lines of scrollback). A character takes the cells of its display width (`Unicode displayWidthOf:`, as wcwidth): a wide one (CJK, emoji) two, the second a continuation cell (writing or erasing either half blanks the other; at the last column it wraps first), a zero-width one (combining marks, ZWJ, variation selectors) none: it is kept with the character before the cursor, drawn over it and copied with it. Every emoji is one grapheme cluster in two cells (as kitty, WezTerm and ghostty do, DEC mode 2027): a pictograph, emoji modifier or regional indicator that continues the cluster printed last (`String>>isGraphemeClusterBoundaryAt:`: after a ZWJ, a skin tone, a flag's second indicator) joins its cell like a zero-width character, as long as the cursor is still right after it and nothing else happened in between; a one-cell cluster that becomes an emoji (a pictograph with U+FE0F or a modifier, a keycap, a flag, a ZWJ sequence; decided from Unicode properties, `TerminalScreen class>>isEmojiCluster:`) takes the next cell too, at the right margin wrapping to the next line first (without autowrap it stays in one). So 👨‍👩‍👧, 👍🏽, ☝🏽, 1️⃣, ❤️, ©️, 🇩🇪 and 🏳️‍🌈 take two cells each, a bare ❤ or © and a lone regional indicator one, and 😀︎ (U+FE0E) two, drawn as text. Programs that count columns with wcwidth (readline) disagree about a ZWJ sequence's or a keycap's width. `TerminalView` draws it in JetBrains Mono (ANSI colors tuned to the Blue Book; box drawing and block elements as rectangles; other characters through the font's fallbacks, a wide one centered in its two cells and smaller only if wider; a wide cell's whole cluster in its two cells, an emoji in color when Twemoji has it (Emoji 14) and as text otherwise; the cursor, also on an emoji in color, and the selection cover both cells), one retained segment per row, the cursor in the overlay (Theme caret blink); keys are encoded as xterm does (⌥ = meta, ⌘C/⌘V/⌘A/⌘K stay with the GUI). An I/O Process ('Terminal pty') reads in 16 KB slices into a queue (it stops reading above 1 MB) and the window's Process interprets it at once, then once per compositor frame (≤ 10 ms), so heavy output redraws at most once per frame. Remote: `@wN.terminal`, role `terminal`, state `rows= cols= cursor=r,c title="…" alt-screen exited=n`, the shown rows as text.

**File Browser** (World menu "File Browser", `FileBrowser open`, `FileBrowser openOn: 'vm/gen/interpreter.c'`, `Tools open: #files with: 'src'`): a column browser (NeXTSTEP's, Finder's column view) in the Blue Book style, from the working directory (the repository) down. A column per folder (`FileColumn`, a ListView): folders first, each sorted by name, names starting with a dot left out; a glyph per entry (a folder, or a page marked by kind: Smalltalk ultramarine, C ink, other text grey, binary halftone), on the right a folder's ▸ or a text file's lines. Selecting a folder opens it as the next column (the columns after it close); selecting a file shows the preview column at the end: name, kind, lines and size above, the modification time (UTC) below, and the text in a `FileViewer` (a read-only `TextEditor`) with line numbers in a gutter (`TextLayout gutter:`): `.st` highlighted as Smalltalk, `.c` and `.h` as C (`CSourceScanner` through `TextHighlighter scanner:`: comments, keywords and types, directives, literals), other text plain, a binary file (a NUL in its first 8 KB) as a hex dump of its first KB; text past 2 MB is cut. Up and down move in a column, right and left between columns, return is right (on a file: into its text); the columns (`FileColumns`) scroll sideways when they do not fit; above them the last folder's path, a link per segment. The viewer draws only the rows shown, so `vm/gen/interpreter.c` (12,681 lines) opens in about 70 ms and scrolls like a short file. Remote: `@wN.column-1` … (labelled with the folder; rows named after the entries, `@wN.column-3.interpreter-c`, state `dir` or `lines=`: `select @wN.column-2 gen`), `@wN.path` (`.path.vm`: a segment), `@wN.file` (the preview's header: name, `right=` kind, lines, size), `@wN.viewer` (state `top=` the first line shown; the lines shown as text), `@wN.info` (modified, opened in).

**System Monitor** (World menu "System Monitor", `SystemMonitor open`, `Tools open: #monitor`): heap and CPU over the last minute or five. Its window's Process samples ten times a second into a ring of five minutes (`SystemMonitorData`): `Smalltalk vm statistics` and every Process's `cpuMicroseconds`. Heap chart: old space in use, eden's fill on top (estimated: the VM reports eden's size and the bytes allocated, not its fill), the budget dashed, a dotted line per full GC; below it the bytes allocated per second and a GC lane (scavenges as high as their pause, full GCs black). CPU chart: each Process's share of the VM's time, stacked, the four busiest named (a Process keeps its shade while it stays among them), the rest grey, idle in halftone, the VM's total as the line. Current values above the charts, hover for the values at a time. Each chart paints only its new columns, one per device pixel, into a ring bitmap drawn in two parts, so the monitor costs its Process under 1% CPU. Remote: `@wN.heap-chart`, `.alloc-chart`, `.cpu-chart` (role `chart`, state `plot= time= max=` and the newest values; `hover --at 10` is 10 s ago), `.heap-values.old` … `.cpu-values.vm` (role `readout`), `.span`, `.status`.
